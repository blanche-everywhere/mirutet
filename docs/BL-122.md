# BL-122 game settings

The settings page and live handling panel share the existing normalized settings,
local storage and `session.setSettings` path. Number fields, sliders and stepper
buttons stay synchronized; empty/invalid drafts retain the last valid value and
restore it on commit. Only number fields that emit an input event become drafts; untouched focus, blur
and Enter preserve imported precision. Restoring the original value also preserves
precision. Numeric text remains a draft while typing, including incomplete decimals.
Change, blur or Enter commits and rounds to the nearest existing slider step
before saving (ties round upward), including audio preferences. Sliders apply
immediately; live stepper clicks commit an active draft before stepping. Imported
fractional handling values and their existing stepper behavior remain unchanged.
Live numeric fields release held inputs and isolate editing keys; Enter or Escape
returns focus to the board. Existing pointer stepper buttons still retain board focus.

Presets are partial patches, not emulation. Timings use 60 Hz and are rounded to
whole milliseconds to match the timing controls:

| Preset | ARR | ARE | IRS / IHS | Single-input 180 |
| --- | --- | --- | --- | --- |
| PPT2 | 33 ms (2F) | 117 ms (7F) | off / off | off |
| TEC | 33 ms (2F) | 100 ms (~6F, Master only) | on / on | off |
| TGM3 | unchanged | 67 ms (4F, fastest Master reference) | on / on | off |

Evidence supplied for BL-122: PPT2 timings are community measurements, with
IRS/IHS absence tested on older builds. TEC ARR comes from a community guide on
the official site; ARE is an expert report specifically for Master. TGM3 ARE is
a reference constant for fastest Master timing, not a universal measured value.
The UI exposes these qualifications in a disclosure. DAS, SDF, DCD, gravity and
spawnDrop are preserved. The default button uses `E.DEFAULT_SETTINGS` directly.

Validation: `npm test`, `npm run build`, `npm run test:browser`,
`npm run test:appearance`, `npm run test:dressup`, `npm run test:settings`.
On Windows set `CHROME_PATH` to the installed Chrome executable.
New regression cases cover invalid input, bounds, repeated stepper and preset
changes, control synchronization, persistence/reload, manual edits, default reset,
keyboard editing, mobile layout and dressup/free-play transitions.
